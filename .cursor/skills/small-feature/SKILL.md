# 小功能快速通道

以一张任务卡完成需求、轻量设计、开发、测试和发布准备。减少重复交接，不减少正确性验证；一小时是估算，不是交付保证。

## 入口与退出

- 先读相关代码、运行配置及适用项目规范；不要求用户回答可从代码查明的事实。
- 只处理一个用户目标，沿用已有架构、技术栈、组件、接口、鉴权、测试和部署通道。
- 权限边界、支付、敏感数据处理、不可逆操作、破坏性接口变更、复杂迁移、新基础设施、多个独立业务模块，均转完整流程。
- 环境不可用、无法定义验收或安全回退时，先报告阻塞；不能假定满足准入条件。
- 用户显式指定原版完整技能时按其执行。更高优先级强制流程或安全门禁不因本技能失效。

## 1. 一次确认

只追问会改变范围、验收、安全或授权的阻塞问题，每轮一个；其余采用有依据的最小方案并写明假设。

在对话中给出以下任务卡，不默认新建文档：

| 字段 | 内容 |
|---|---|
| 目标与范围 | 谁在何处得到什么结果；明确非目标 |
| 验收 | 可观察的主路径结果、相关边界或失败行为 |
| 实现 | 沿用什么；改哪些已定位文件；兼容性影响 |
| 步骤 | 3～5 步，每步对应验证方式；命令以实际项目配置为准 |
| 风险与回退 | 主要风险；如何只撤回本次改动或恢复上一发布版本 |
| 发布 | 仅本地交付，或用户已授权的具体环境；未知则待确认 |

请用户一次确认任务卡后执行。若对话中已有等价内容且用户已明确批准，复用确认，不再重复提问。范围、风险或发布授权发生变化时才重新确认相关部分。

任务卡确认后连续完成开发和验证，不再逐阶段等待批准；不串行调用原版 `brainstorming`、`writing-plans`、`executing-plans` 重建文档或重做确认。

## 2. 开发与修复

- **必读技能：** `karpathy-guidelines`，入口 `.cursor/skills/karpathy-guidelines/SKILL.md`。它贯穿开发，不只用于缺陷修复。
- 前端改动读取 `.cursor/rules/frontend-developer.mdc`；涉及后端设计决策时读取 `.cursor/rules/backend-architect.mdc`，只应用当前改动相关规范。
- 先定义验收检查和最小回归测试，能自动化的行为先运行测试观察预期失败，再做最小实现、重跑验证。
- 不新增无关抽象、不顺手重构，不覆盖用户已有改动。测试规模随影响面增加，不按文件数量机械判断风险。
- 修 Bug 按“复现 → 根因 → 最小修复 → 原场景及相关回归”执行；`karpathy-guidelines` 不能替代诊断和测试。
- 共享契约或多个模块受影响时，重新评估准入，不能靠继续加补丁维持一小时承诺。

## 3. 验证门槛

先核对改动范围，再运行与影响面匹配的检查，记录实际命令及结果：

| 改动 | 必要证据 |
|---|---|
| 业务逻辑或接口 | 主路径及相关边界/失败用例；使用现有单元或接口测试框架 |
| Web 交互 | **必读技能：** `webapp-testing`，入口 `.cursor/skills/webapp-testing/SKILL.md`；运行实际操作断言，检查相关页面、错误状态和浏览器错误 |
| 前端布局 | 涉及视口下的截图或实际渲染检查，确认文本、控件和响应式布局 |
| 构建与静态检查 | 使用项目已有、与改动相关的构建、类型或 lint 命令 |

Web 验收不能代替业务层测试，构建成功不能代替功能通过。没有测试框架时先说明，选可重复的最小验证；不能为赶时间新建整套基础设施，也不能把未执行写成通过。

验证失败先诊断再修复，重跑失败项及相关回归。环境阻塞或时间不足时报告“已实现但未完成验证”及具体缺口，不宣称完成、不进入发布。

## 4. 发布与交付

- 默认只交付本地实现和验证证据，不自动 commit、push 或部署；这些操作分别以用户授权及项目门禁为准。
- 需要部署时读取 `.cursor/rules/devops-automator.mdc`，确认具体目标环境、已有部署命令、配置与回退方式后再执行。
- 持有凭据、构建成功、窗口将关闭或已批准任务卡，都不等于授权生产发布。仅能发布到已明确授权的环境。
- 沿用已有流水线；不为小功能新建 CI/CD、蓝绿集群、监控或追踪平台。
- 已部署后执行健康检查和关键路径冒烟；失败按确认的回退方案处理，回退无法执行时立即报告，不继续扩大操作。
- 最后简述改动、验证证据、剩余风险、发布状态。明确区分“未发布”“待授权”“已发布并验证”“发布失败/已回退”，发布准备完成不算已发布。

## 时间预算

| 环节 | 建议分钟 |
|---|---:|
| 理解与确认 | 8 |
| 轻量设计与计划 | 5 |
| 开发 | 27 |
| 验证与修复 | 12 |
| 发布或交付 | 8 |

确认已完成的环节不重做，未授权发布的时间可用于验证。预计超时即说明完成度、原因和剩余工作，与用户缩减范围、拆分或重新估时；不静默删验收项。

## 常见误区与停止信号

| 误区 | 处理 |
|---|---|
| “普通筛选也要先写设计文档和详细计划” | 满足准入时，一张任务卡确认后连续执行 |
| “只改两行权限，所以还是小功能” | 依据风险升级，不依据行数放行 |
| “只剩五分钟，已投入很多，测试以后补” | 报告未验证，保留验证门槛，不宣称完成或发布 |
| “有生产凭据，可以顺便上线” | 停在交付或待授权状态 |

出现越权、不可逆变更、无法回退、验收缺口或流程冲突，停止受影响的操作并说明原因，保留已有成果；不能用“快速”解释绕过。

## 调用示例

“按小功能快速通道：为现有订单列表增加状态筛选，复用已有接口；验收包含筛选、清空、空结果；只在本地验证，不部署。”

先查列表和接口实现，形成任务卡并确认；若发现必须改变数据权限，升级说明，不直接编码。
