# AI 与高校课程考核资讯 PRD（自动采集与情报库）

---

## 一、需求背景

### 1.1 用户痛点

用户每天需要跟进 AI 与高校课程考核相关的政策与热点信息，目前完全靠人工：

1. **获取负担**：信息散落在政府网站、公众号、新闻门户等多个渠道，每天逐个翻查，费时且容易漏。
2. **沉淀缺失**：看过的信息散落在浏览器历史与聊天记录里，想引用「上个月那个文件」时找不到原文与出处。
3. **闭环断裂**：看到「某省出台 AI 参与课程考核试点」这类值得跟进的政策后，研读、评估影响等动作靠记忆，没有进入任务体系被真正执行。

### 1.2 典型用户场景

- **场景 A（自动入库）**：用户预先配置了若干信息源（政策网站、资讯 RSS 等）。每天系统已自动把新内容抓进资讯库，AI 完成摘要与分类打标，打开资讯页直接浏览，不再逐站翻找。
- **场景 B（每日简报）**：早上打开资讯页点「生成今日简报」，一页读完当日新增的政策动向与热点速览，重要条目标星待细读。
- **场景 C（检索回溯）**：想找「上个月关于 AI 赋能高校教学的文件」，在资讯库按分类 + 关键词检索，秒级定位并跳转原文。
- **场景 D（转任务）**：看到一条值得跟进的政策，点「转为任务」，系统预填标题与描述（含原文链接），确认后进入现有任务看板跟进。
- **场景 E（来源故障）**：某来源网站改版导致解析失败，来源管理页显示失败状态与原因；用户修正解析规则或更换来源后恢复采集。

### 1.3 目标与范围

| 类型 | 说明 |
| --- | --- |
| 目标 | 建立「政策热点情报库」：自动采集 → AI 摘要打标 → 存档检索 → 每日简报 → 转任务，形成从「看到」到「处理」的闭环 |
| P0（首期） | US-01 订阅来源管理；US-02 定时采集与去重；US-03 资讯存档与检索；US-04 AI 摘要与自动打标；US-05 每日简报；US-06 资讯转任务 |
| P1（规划，建议项、待确认） | AI 联网搜索聚合（关键词订阅补充热点发现）；简报每日定时自动生成；简报站外推送（邮件）；资讯与项目关联 |
| 本期不做 | 全网任意爬取（只抓用户显式配置的来源）；需登录或付费渠道的内容获取；AI 自动创建任务（转任务必须经用户确认）；资讯评论、多人协作与对外分享；原始 HTML 与图片的转载存储（只存正文文本，口径见 A.4 第 6 条） |

### 1.4 环境/兼容/前置结论

以下结论来自对本仓库代码的核对（后端 `backend/src/main/java/com/aiassistant/`，前端 `frontend/src/`，迁移脚本 `backend/src/main/resources/db/migration/`），本文档所有「现状」描述以此为准：

1. **技术形态**：React 19 + react-router 7 + @tanstack/react-query 5 前端；Spring Boot 单体 + H2 文件库 + Flyway 迁移（`ddl-auto: validate`，改结构必须新增迁移脚本）；JWT 登录鉴权，数据按 `owner_id` 用户隔离（tag 等实体均含 owner 列），系统无角色体系，所有功能的使用者都是「登录用户本人」。
2. **AI 基础已具备**：用户级 AI 总开关已落地（`user_settings.ai_enabled`，默认关闭，关闭时 AI 接口返回 AI_DISABLED）；`ai` 包已具备 AI 客户端与限流器（AiClient / OpenAiCompatibleClient / AiRateLimiter）；错误码 AI_DISABLED / AI_TIMEOUT / AI_UNAVAILABLE / AI_RATE_LIMITED / AI_EMPTY_RESULT 已在 ErrorCode 冻结。本 PRD 的 AI 故事在其上实现，**不另设开关**。
3. **调度先例**：`config/SchedulingConfig` 已启用 @EnableScheduling，现有两条分钟级短任务（计时兜底、每日 03:30 对账），使用默认单线程调度器。资讯采集是批量、可能分钟级的任务，需要独立执行线程池与单来源超时控制，避免阻塞现有定时任务与在线接口（见 3.2）。
4. **解析依赖缺失**：后端 pom 现无 RSS/HTML 解析类依赖，采集能力需引入解析库（选型见 A.4 第 1 条）。
5. **错误体**：统一 ApiError（status / code / error / message / timestamp），错误码只增不改，前端按 code 判分支。
6. **前端页面现状**：路由仅 /login、/today、/board、/tasks/:id、/settings；资讯模块新增独立页面与导航入口。
7. **标签可复用**：tag 模块按用户隔离，资讯打标复用现有标签体系，不另建标签。
8. **任务通道**：转任务走现有任务创建通道，任务创建沿用现有审计留痕（TaskActivityLog）。

## 二、用户故事

> 本章按功能点组织，US-01 ～ US-06 均为 P0。AI 相关故事（US-04 / US-05）复用现有用户级 AI 总开关，开关关闭时资讯模块其余功能照常可用。

### US-01：订阅来源管理

**用户故事**

作为登录用户，我希望维护自己的订阅来源（RSS 源或网页列表页），以便系统按我关注的渠道自动采集。

**故事详述**

- **功能描述**：资讯页提供「来源管理」。来源分两类：RSS（填源地址即可）；网页列表（填列表页 URL 与解析规则——列表项、标题、链接、可选发布时间的提取规则）。字段：名称、类型、URL、默认分类、启用状态、解析规则（网页类型）。
- **试抓**：保存前可对来源立即抓取一次，返回抓到的条数与标题预览，用于验证配置；试抓结果不写库。
- **健康状态**：来源列表展示最近一次抓取时间与结果（成功条数 / 失败原因），异常来源显著标识。
- **核心规则**：
  1. 来源按用户隔离：只能看到、操作本人来源。
  2. URL 仅接受 http/https；每用户来源数量有上限（建议 20，见 A.4 第 4 条）。
  3. 停用来源不参与自动采集，历史资讯保留；删除来源需二次确认，已抓取资讯保留并仍可检索（来源显示名称快照）。
  4. 试抓失败仍允许保存（来源标为异常），以便用户先保存再调整；robots 禁止抓取的来源不允许保存（见 3.1）。

**验收标准**

- AC 1.1 `[前端]` 资讯页「来源管理」支持新增 / 编辑 / 启停 / 删除两类来源；网页类型含解析规则配置项
- AC 1.2 `[系统]` 来源按用户隔离：接口只返回与操作本人来源，他人来源返回 NOT_FOUND
- AC 1.3 `[交互]` 提供「试抓」：立即抓取一次并返回条数与标题预览；试抓结果不写入资讯库
- AC 1.4 `[系统]` URL 仅接受 http/https，非法值返回 VALIDATION_FAILED；来源数量达上限时拒绝新增并提示
- AC 1.5 `[前端]` 来源列表展示最近抓取时间、结果状态与失败原因；异常来源有显著标识
- AC 1.6 `[系统]` 删除来源需二次确认；删除后其历史资讯保留且可检索
- AC 1.7 `[系统]` robots 禁止抓取的 URL 在保存与试抓时被拒绝并提示

### US-02：定时采集与去重

**用户故事**

作为登录用户，我希望系统每天定时抓取我启用的来源、自动去重入库，以便不漏新政策也不重复堆积。

**故事详述**

- **功能描述**：每日定时抓取全部启用来源，新内容入库为「未读」条目；抓取在后台异步执行。
- **核心规则**：
  1. 逐来源独立执行：单来源失败（超时、解析失败）不影响其他来源；单来源单次入库条数有上限（建议 50，见 A.4 第 4 条），超出部分丢弃并在来源结果中注明。
  2. 去重：同一用户内归一化链接相同的条目不重复入库。
  3. 失败处理：失败原因写入来源健康状态；连续失败达阈值（建议 3 次，见 A.4 第 5 条）后停止该来源自动抓取并标为「异常」，需人工修复后重新启用。
  4. 抓取礼貌：遵守 robots 协议，对同一站点请求有间隔与超时限制（见 3.1 / 3.2）。
  5. 手动触发：资讯页提供「立即采集」，对全部启用来源立即抓取一轮，异步执行（限流见 A.4 第 11 条）。
- **与 AI 的关系**：采集本身不依赖 AI；AI 开关关闭时条目照常入库，摘要与标签为空。

**验收标准**

- AC 2.1 `[系统]` 每日按配置时间对所有启用来源执行采集，逐来源独立执行、互不影响
- AC 2.2 `[性能]` 采集全程后台异步；执行期间列表 / 检索等在线接口 P95 不劣化（指标见 3.2）
- AC 2.3 `[系统]` 同一用户内归一化链接相同的条目不重复入库
- AC 2.4 `[系统]` 单来源单次入库条数不超过上限，超出部分丢弃并在来源结果中注明
- AC 2.5 `[系统]` 单来源抓取失败不影响其他来源；失败原因与时间写入来源健康状态
- AC 2.6 `[系统]` 来源连续失败达阈值后停止自动抓取并标记「异常」；重新启用后恢复
- AC 2.7 `[前端]` 提供「立即采集」入口，触发后异步执行并反馈已触发
- AC 2.8 `[系统]` 新入库条目默认「未读」；AI 不可用时摘要与标签为空，条目仍正常入库与展示

### US-03：资讯存档与检索

**用户故事**

作为登录用户，我希望资讯库支持筛选、关键词检索、已读与星标管理，以便积累的情报找得回、看得完。

**故事详述**

- **功能描述**：新增独立「资讯」页面。列表展示标题、来源、分类、发布时间、已读 / 星标状态与一行摘要；详情展示原文链接、抓取正文、AI 摘要与要点、标签与关联任务。
- **检索与筛选**：筛选维度：分类、来源、标签、日期区间、星标、已读 / 未读，可组合；关键词检索覆盖标题与抓取正文。
- **核心规则**：
  1. 已读 / 未读、星标为用户操作，切换即时生效。
  2. 分类为单选枚举（建议：政策文件 / 行业热点 / 技术动态 / 其他，集合见 A.4 第 12 条）；标签复用现有标签体系。
  3. 点击标题在新窗口打开原文链接；详情页同时展示抓取正文便于站内检索定位（正文存储口径见 A.4 第 6 条）。
  4. 资讯按用户隔离，检索与浏览仅及本人条目。

**验收标准**

- AC 3.1 `[前端]` 新增「资讯」页面与导航入口；列表展示标题、来源、分类、时间、已读 / 星标与摘要行
- AC 3.2 `[系统]` 列表支持分类、来源、标签、日期区间、星标、已读筛选，条件可组合，分页返回（20 条 / 页）
- AC 3.3 `[系统]` 关键词检索覆盖标题与抓取正文
- AC 3.4 `[性能]` 列表与检索接口 P95 ≤ 500ms（20 条 / 页）
- AC 3.5 `[前端]` 详情页展示原文链接（新窗口跳转）、正文、摘要、标签与关联任务
- AC 3.6 `[交互]` 已读 / 星标切换即时保存；保存失败时状态回弹并提示
- AC 3.7 `[系统]` 资讯按用户隔离：他人条目不可见、不可检索（直接调用返回 NOT_FOUND）

### US-04：AI 摘要与自动打标

**用户故事**

作为登录用户，我希望新资讯入库后 AI 自动生成摘要、要点与建议分类标签，以便把「逐篇细读」变成「扫摘要、看要点」，分类标签不用手工整理。

**故事详述**

- **功能描述**：新条目入库后异步发起 AI 处理，生成：一句话摘要、要点（3–5 条）、建议分类（枚举内选一）、建议标签（0–3 个），结果写入条目。
- **确认方式**：摘要与要点为只读展示内容；建议分类 / 标签在详情页以「待采纳」形态展示，用户可一键采纳，也可修改后保存。
- **核心规则**：
  1. 全程异步：AI 处理不阻塞采集与浏览；处理状态（待处理 / 处理中 / 完成 / 失败）在条目上可查。
  2. 开关行为：复用用户级 AI 总开关。关闭时不发起 AI 请求，条目照常入库与展示，摘要与标签为空。
  3. 降级与重试：AI 失败不影响条目可用性；详情页提供「重新生成」。
  4. 发送边界：仅发送标题与抓取正文（截断上限见 A.4 第 6 条），不包含用户任务、设置等其他数据。

**验收标准**

- AC 4.1 `[系统]` 新条目入库后自动异步发起 AI 摘要与打标，结果写入条目，处理状态可查
- AC 4.2 `[系统]` AI 总开关关闭时不发起任何 AI 请求，条目正常入库与展示
- AC 4.3 `[前端]` 详情页展示摘要与要点；建议分类 / 标签以可采纳形态展示，采纳后条目更新
- AC 4.4 `[交互]` 用户可修改 AI 建议的分类与标签后保存，修改即时生效
- AC 4.5 `[性能]` 单条 AI 处理 P95 ≤ 15s（异步）；失败不影响条目入库与浏览
- AC 4.6 `[系统]` AI 处理失败的条目保留「重新生成」入口；重试不产生重复条目

### US-05：每日简报

**用户故事**

作为登录用户，我希望一键生成当日新增资讯的 AI 简报，以便一页读完政策动向与热点，不再逐条翻。

**故事详述**

- **功能描述**：资讯页提供「生成今日简报」入口。AI 基于当日新入库条目的标题、分类与摘要生成简报（政策动向 / 热点速览 / 建议关注），展示在卡片中。
- **核心规则**：
  1. 简报仅基于本人资讯库当日数据生成；当日无新条目时返回空态文案，不调用 AI。
  2. 简报为只读展示，不落库（存档与否见 A.4 第 7 条）；提供「复制」「关闭」。
  3. 受 AI 总开关控制：关闭时入口不出现，接口返回 AI_DISABLED。
  4. 简报基于生成时刻已入库条目，不等待进行中的 AI 处理。

**验收标准**

- AC 5.1 `[前端]` 资讯页出现「生成今日简报」入口；AI 总开关关闭时入口不出现
- AC 5.2 `[系统]` 请求后返回当日简报文本；当日无新条目时返回空态文案，不调用 AI
- AC 5.3 `[系统]` 简报仅基于本人数据生成
- AC 5.4 `[交互]` 提供复制与关闭动作，复制成功有提示
- AC 5.5 `[性能]` 简报接口 P95 ≤ 20s；等待期间可关闭展示区，不阻塞页面其他操作
- AC 5.6 `[系统]` 简报不写入任何数据

### US-06：资讯转任务

**用户故事**

作为登录用户，我希望把一条资讯一键转为待办任务，以便「研读政策、评估对考核方案的影响」这类跟进动作进入现有任务体系被真正执行。

**故事详述**

- **功能描述**：资讯详情页「转为任务」按钮，弹出确认框：预填任务标题（「研读：<资讯标题>」，超长截断）与描述（含原文链接、AI 摘要与要点），用户可修改并可选择项目 / 标签，确认后创建。
- **核心规则**：
  1. 走现有任务创建通道创建，默认状态 TODO，优先级按现有推导规则；不自动指派项目 / 标签。
  2. 创建成功后资讯条目记录关联任务并在详情页展示（可跳转）；同一资讯允许多次转任务，已有关联会展示以避免重复创建。
  3. 关联任务被删除后，资讯侧关联显示「任务已删除」，资讯数据不受影响。
  4. 转任务不触发任何 AI 请求。

**验收标准**

- AC 6.1 `[前端]` 详情页提供「转为任务」；确认框预填标题与描述（含原文链接），可修改并选择项目 / 标签
- AC 6.2 `[系统]` 确认后经现有任务创建通道创建任务（状态 TODO）；资讯记录关联任务
- AC 6.3 `[前端]` 详情页展示已关联任务列表并可跳转；关联任务已删除时显示「任务已删除」
- AC 6.4 `[交互]` 取消转任务不创建任何数据
- AC 6.5 `[审计]` 转任务创建的任务沿用现有任务创建审计留痕

## 三、非功能性需求

### 3.1 安全性

| 需求项 | 说明 |
| --- | --- |
| 抓取范围 | 仅抓取用户显式配置的 http/https 来源；不抓取需登录、付费内容；遵守 robots 协议，禁止抓取的来源拒绝保存并提示 |
| 内容防护 | 抓取内容一律提取为纯文本存储与渲染，不执行其中的脚本与样式；原文查看通过外链跳转 |
| 数据隔离 | 来源、资讯、简报均按 owner 隔离；他人资源一律 NOT_FOUND，不泄露存在性 |
| AI 发送边界 | 发送给 AI 的内容仅限资讯标题与抓取正文（截断）；不包含用户任务、设置等数据；AI 调用遵守用户级总开关与 AI 能力包既有安全约束 |
| 配置安全 | AI 服务密钥等走服务端环境变量，不下发前端 |
| 频率限制 | 手动「立即采集」按用户限流（阈值见 A.4 第 11 条）；AI 请求沿用现有 AI 限流器 |

### 3.2 性能指标

| 需求项 | 指标 |
| --- | --- |
| 资讯列表 / 筛选 / 检索接口 | P95 ≤ 500ms（20 条 / 页） |
| 单来源采集 | 单次 ≤ 60s，超时按失败处理，不影响其他来源 |
| 全量采集任务 | 100 个启用来源 ≤ 10min 完成（异步、逐来源独立，结果在来源健康状态可见） |
| 采集期间在线接口 | 不受影响（采集使用独立执行线程池，不占用 Web 线程与现有调度线程） |
| AI 单条摘要与打标 | P95 ≤ 15s（异步，不阻塞浏览） |
| 简报生成 | P95 ≤ 20s |
| 来源试抓 | ≤ 15s |

### 3.3 数据一致性

- 去重以归一化链接为准（同一用户内唯一约束），重复抓取不产生重复条目。
- 采集落库逐条事务：单条解析或写入失败只跳过该条，不产生「半条」记录，不影响其余条目。
- AI 摘要「先入库后补写」：条目先可见，摘要完成后补写；摘要缺失不影响条目可用性。
- 简报基于生成时刻已入库条目计算，生成后不因新入库条目自动变化。

### 3.4 存储架构（建议）

| 数据 | 说明 |
| --- | --- |
| info_sources | 订阅来源：owner_id、名称、类型（RSS / 网页）、URL、解析规则、默认分类、启用状态、健康状态（最近抓取时间 / 结果 / 连续失败计数） |
| info_items | 资讯条目：owner_id、source_id、标题、归一化链接、正文文本、发布时间、分类、标签、AI 摘要 / 要点 / 处理状态、已读、星标、关联任务、入库时间；同一用户内归一化链接唯一 |
| 简报 | P0 不落库（展示即弃）；是否存档见 A.4 第 7 条 |
| 正文口径 | 只存提取后的正文文本（用于检索与 AI），不存原始 HTML 与图片（口径确认见 A.4 第 6 条） |
| 迁移 | 新增 Flyway 迁移脚本建表，不由实体反推 |

## 四、逻辑断言矩阵

| Given | When | Then |
| --- | --- | --- |
| 来源为 RSS 且配置正确 | 用户点击「试抓」 | 返回抓到条数与标题预览，资讯库不新增数据 |
| 来源为网页且解析规则错误 | 用户点击「试抓」 | 返回 0 条与失败原因；仍允许保存，来源标为异常 |
| 目标站点 robots 禁止抓取 | 保存或试抓该来源 | 拒绝并提示「该来源禁止自动抓取」，不入库 |
| 存在多个启用来源 | 每日定时采集触发 | 逐来源独立抓取；失败来源记录原因，不影响其他来源 |
| 同一用户已有同链接条目 | 采集再次抓到该链接 | 不重复入库 |
| 单来源单次抓取条数超上限 | 采集落库 | 入库数不超过上限，超出部分在来源结果中注明 |
| 来源连续失败达阈值 | 定时采集触发 | 停止该来源自动抓取并标记「异常」；重新启用后恢复 |
| 用户点击「立即采集」 | 采集执行中 | 异步执行，列表 / 检索接口正常响应 |
| AI 总开关关闭 | 新条目入库 | 条目正常入库与展示，无摘要与建议，不发起 AI 请求 |
| AI 总开关打开 | 新条目入库 | 异步生成摘要与建议分类 / 标签并写入条目 |
| AI 总开关打开 | AI 处理失败 | 条目可用、摘要为空；详情页可「重新生成」，重试不产生重复条目 |
| AI 总开关打开 | 采纳 AI 建议分类 / 标签 | 条目分类 / 标签更新为建议值 |
| 任意 AI 状态 | 按分类 + 关键词检索 | 仅返回本人条目；他人条目不可见 |
| 当日无新条目 | 生成今日简报 | 返回空态文案，不调用 AI |
| AI 总开关关闭 | 调用简报接口 | 返回 AI_DISABLED（HTTP 403） |
| 资讯详情 | 确认「转为任务」 | 经现有通道创建任务（TODO），资讯记录关联并可跳转 |
| 资讯详情 | 取消「转为任务」 | 不创建任何数据 |
| 关联任务已被删除 | 查看资讯详情 | 关联显示「任务已删除」，资讯其余内容不受影响 |
| 未登录 | 调用任意资讯接口 | 返回 UNAUTHORIZED（HTTP 401） |
| 他人来源 / 条目 | 直接调用对应接口 | 返回 NOT_FOUND，不泄露存在性 |

## 五、异常处理规范

### 5.1 采集类异常

| 场景 | 用户提示 | 系统行为 |
| --- | --- | --- |
| 来源不可达（域名失效 / 连接超时） | 来源列表标「抓取失败：<原因>」 | 记录失败时间与原因；连续失败达阈值停抓并标异常 |
| 网页解析失败或抓到 0 条 | 来源列表标「解析异常」 | 不写库；试抓场景提示检查解析规则 |
| robots 禁止抓取 | 「该来源禁止自动抓取」 | 拒绝保存 / 入库，来源标异常 |
| 单条内容解析失败 | 无感（不打扰） | 跳过该条继续，其余条目照常入库 |
| 超过单来源单次条数上限 | 无感 | 截断入库并在来源结果中注明 |
| 试抓超时 | 「试抓超时，请检查来源地址」 | 返回 FETCH_TIMEOUT，配置可保存 |

### 5.2 AI 类异常

| 场景 | 用户提示 | 系统行为 |
| --- | --- | --- |
| AI 总开关关闭 | 入口不出现；直接调用提示「AI 能力未开启」 | 返回 AI_DISABLED（HTTP 403），不调用 AI 服务；条目照常入库 |
| AI 超时 / 不可用 / 返回空 | 详情页处理状态显示「AI 处理失败」 | 条目可用，摘要为空；沿用 AI_TIMEOUT / AI_UNAVAILABLE / AI_EMPTY_RESULT，提供「重新生成」 |
| 简报当日无数据 | 空态文案「今天还没有新的资讯」 | 返回空集（HTTP 200），不调用 AI |

### 5.3 表单与权限异常

| 场景 | 用户提示 | 系统行为 |
| --- | --- | --- |
| URL 非法 / 日期区间非法 / 表单缺项 | 「来源地址不正确」等字段级提示 | 返回 VALIDATION_FAILED（HTTP 400），不落库 |
| 来源数量达上限 | 「订阅来源已达上限」 | 返回 VALIDATION_FAILED（上限值见 A.4 第 4 条） |
| 手动采集触发过频 | 「操作太频繁，请稍后再试」 | 返回 FETCH_RATE_LIMITED（HTTP 429） |
| 访问他人来源 / 条目 | 与现有资源接口一致 | 返回 NOT_FOUND（HTTP 404） |
| 未登录 | 跳转登录页 | 返回 UNAUTHORIZED（HTTP 401） |

### 5.4 异常返回示例

```json
{
  "status": 504,
  "code": "FETCH_TIMEOUT",
  "error": "Gateway Timeout",
  "message": "试抓超时，请检查来源地址",
  "timestamp": "2026-10-24T09:30:00Z"
}
```

错误体沿用系统统一格式（status / code / error / message / timestamp），错误码只增不改：本 PRD 新增 FETCH_TIMEOUT、FETCH_FAILED、PARSE_FAILED、ROBOTS_DISALLOWED、FETCH_RATE_LIMITED；AI 相关沿用已冻结的 AI_DISABLED / AI_TIMEOUT / AI_UNAVAILABLE / AI_RATE_LIMITED / AI_EMPTY_RESULT。采集失败明细不抛全局错误体，呈现在来源健康状态中。

### A.4 待确认项（评审拍板）

1. **解析库选型**：RSS 与 HTML 解析的具体库（Java 生态如 Rome / jsoup 等）与版本，随技术方案确认。
2. **网页解析规则的配置形态**：a) 用户填写 CSS 选择器（灵活、门槛高，推荐）；b) 预置常用站点模板（易用、维护成本高）。影响 US-01 的表单设计。
3. **抓取时间与频率**：默认每日 1 次（建议清晨，与现有 03:30 对账错峰）；是否需要按来源配置时间 / 频率。
4. **数量上限**：每用户来源数上限（建议 20）与单来源单次入库条数上限（建议 50）。
5. **连续失败停抓阈值**：建议 3 次；达到后标「异常」并停止自动抓取。
6. **正文存储口径与 AI 截断上限**：只存正文文本、不存 HTML / 图片（版权与存储成本）；发送给 AI 的正文截断上限（建议 ≤ 5000 字）。
7. **简报存档**：P0 展示即弃；是否需要每日定时自动生成并留存历史简报（涉及存储与 AI 成本，建议 P1）。
8. **简报入口与提醒形态**：资讯页内生成（P0 既定）；今日页是否增加「昨日新增 N 条资讯」提醒卡片。
9. **资讯条目变更留痕**：分类 / 标签 / 星标等修改是否需要审计（现有审计体系面向任务，资讯侧接入需新增范围）。
10. **AI 联网搜索聚合**（P1）：按关键词订阅、由 AI 检索热点补充入库；涉及成本、原文可追溯性与合规评估，单独立项确认。
11. **限流阈值**：手动「立即采集」每用户每日次数上限；AI 打标随采集批量触发时与现有 AI 限流器的配额关系。
12. **分类枚举集合**：政策文件 / 行业热点 / 技术动态 / 其他（建议）；是否允许用户自定义分类。
13. **首批来源清单**：用户实际关注的站点 / 公众号清单及其 RSS 可用性（公众号无官方 RSS，替代渠道需逐一验证），作为 US-01/02 验收的真实数据集。
