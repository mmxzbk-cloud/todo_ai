# 智能任务管理增强 PRD（AI 能力包与耗时统计）

---

## 一、需求背景

### 1.1 用户痛点

系统目前是一个「全手动」的任务管理工具：优先级靠用户自己按重要/紧急判断，任务能不能交给 AI 做靠用户自己在详情页表单里选，方案思路要自己想。随着任务数量增加，三类负担越来越明显：

1. **判断负担**：每个任务都要自己填重要性、紧急性，再人工评估「这件事能不能让 AI 做」。用户往往拿不准、懒得填，导致字段大量留空（`ai_replaceable` 现状允许 NULL=未评估，实际使用中多数任务停留在未评估）。
2. **起步负担**：面对一个模糊的任务（例如「整理季度数据」），写不出下一步行动，任务一放就是好几天。
3. **复盘负担**：计时数据都在流水表里，但用户只能看到单个任务的累计分钟数，回答不了「我今天一共投入了多少小时」「这个项目这个月花了多少时间」这类汇总问题。

### 1.2 典型用户场景

- **场景 A（优先级）**：用户上午一口气录入了 8 个任务，没填重要性/紧急性。打开任务列表，希望系统直接给每个任务一个建议优先级和一句理由，自己扫一眼，认可的就点采纳，不认可的维持原状。
- **场景 B（方案建议）**：用户接到任务「给新同事配置开发环境」，不知道从哪下手。在任务详情页点「AI 建议」，得到几步思路，点采纳后思路填入「下一步行动」，自己再改两笔就保存了。
- **场景 C（可替代性评估）**：用户在批处理一批琐碎任务时，希望系统告诉每个任务属于「可由 AI 解决 / 部分可 / 不可」，把可以交出去的挑出来。
- **场景 D（耗时统计）**：周五下午，用户想回顾本周每天各投入了多少时间、哪个项目占了大头，系统里没有这个页面，只能逐个任务点开详情自己加。
- **场景 E（不想要 AI）**：用户在涉密环境使用本工具，不希望任何内容发给外部 AI 服务。在设置里把 AI 能力总开关关掉后，系统行为与现在完全一致。

### 1.3 目标与范围

| 类型 | 说明 |
| --- | --- |
| 目标 | 1）把「判断、起步、评估」三类手工劳动交给 AI 建议，但所有写入都由用户确认；2）补齐耗时汇总统计；3）提供总开关，保证 AI 能力可整体停用 |
| P0（首期） | US-01 AI 能力总开关；US-02 AI 建议任务优先级；US-03 AI 生成解决方案建议；US-04 AI 评估任务可替代性；US-05 任务总耗时统计 |
| P1（规划，建议项、待确认） | US-06 AI 拆解子任务；US-07 每日工作总结；US-08 计时备注自动生成建议；US-09 周复盘草稿生成 |
| 本期不做 | AI 自动执行任务（只建议、不执行）；AI 自动修改任何任务字段（一律用户确认后写入）；AI 机会表（ai_opportunities）、Skill 库（skills）的业务功能（数据库已建表，业务模块后续单独立项）；多语言建议输出 |

### 1.4 环境/兼容/前置结论

以下结论来自对本仓库代码的逐项核对（后端 `backend/src/main/java/com/aiassistant/`，前端 `frontend/src/`，建表脚本 `backend/src/main/resources/db/migration/V1__init_schema.sql`），本文档所有「现状」描述以此为准：

1. **技术形态**：React 19 单页前端 + Spring Boot 单体后端 + H2 文件库；登录用户之间按 `owner_id` 隔离数据，系统没有角色体系（`users` 表无角色列），所有功能的使用者都是「登录用户本人」。
2. **优先级现状**：任务已有重要性（importance：高/中/低）与紧急性（urgency：高/中/低）两个字段，优先级（priority：P0–P3）是存储字段，默认按「重要性权重 + 紧急性权重（高=0/中=1/低=2），求和封顶 3」推导；请求显式指定优先级时手工值优先，且后续编辑不会悄悄覆盖手工值。已有单独改优先级的接口（PATCH /api/v1/tasks/{id}/priority）。**系统目前没有任何 AI 参与的优先级判断。**
3. **AI 可替代性字段现状**：任务表已有 `ai_replaceable`（三态：NULL=未评估 / TRUE / FALSE）与 `ai_replacement_note`（说明文字，上限 2000 字）两个字段，**由用户在任务详情页表单里人工填写**（建表注释明确「本轮人工填写，不调模型」），修改会留变更审计。
4. **已建表但无业务代码**：数据库已建 `ai_opportunities`（每日 AI 机会，含 `ai_can_replace`，取值 YES/PARTIAL/NO/UNKNOWN）、`skills`、`skill_usage_logs`、`weekly_reviews`（周复盘）四组表，后端尚无对应实体、接口与页面。本 PRD 的 AI 评估结果落点以 `tasks.ai_replaceable` 为主，`ai_opportunities` 相关能力本期不做。
5. **设置页现状**：/settings 页面只有项目管理（新建/归档）与标签管理（新建/删除），「显示已归档」只是页面内临时勾选，**没有任何持久化的用户偏好存储**。AI 总开关需要新增用户级偏好存储。
6. **计时现状**：同一用户同时只能有一段计时（冲突返回 TIMER_ALREADY_RUNNING）；耗时流水来源两种（TIMER=计时器 / MANUAL=手工补录），每段记录分钟数由服务端算好落库；任务表上的 `actual_minutes` 是冗余累计列，权威数据在 `task_time_logs` 流水表，另有每日对账任务按流水重算纠偏；未结束的计时超过 12 小时会被兜底截断。开始计时会把 TODO 任务推进到 DOING。
7. **耗时展示现状**：任务详情页展示「耗时（实际 / 预计）分钟」与耗时明细（最近 50 条流水，页面底部把返回的明细求和显示「合计 X 分钟」）；看板与任务卡片展示「实际 X / 预计 Y 分钟」。**没有按天汇总、没有按项目汇总、没有独立统计页面**；当某任务流水超过 50 条时，详情页明细合计会小于真实累计值（口径缺口，见 US-05）。
8. **无 AI 集成**：后端没有任何大模型/AI 服务的配置与调用代码，`application.yml` 中无相关配置项。AI 能力包属于从零新增，AI 服务与模型选型见 A.4 待确认项。

## 二、用户故事

> 本章按功能点组织，每个功能点独立成节。故事详述内依次给出：功能描述、用户价值、入口与交互方式、核心规则（含开关行为）。验收标准写成可勾选条目，评审时逐条打勾。

### US-01：AI 能力总开关

**用户故事**

作为登录用户，我希望在设置页一键启用或关闭全部 AI 能力，以便在不想要 AI 的时候系统行为与现在完全一致。

**故事详述**

- **功能描述**：设置页新增「AI 能力」区块，内含一个总开关。开关状态按用户隔离保存，重新登录后保持。开关只控制 AI 能力包（US-02 / 03 / 04 / 06 / 07 / 08 / 09），不影响耗时统计（US-05）与现有全部功能。
- **用户价值**：把「要不要用 AI」的决定权交给用户；对不想用、不敢用的用户，系统退回纯净形态，不增加任何打扰。
- **入口与交互方式**：导航「设置」→ 新区块「AI 能力」。开关为单个复选框或滑动开关，旁边一句话说明「关闭后，所有 AI 入口将隐藏，系统不会发起任何 AI 请求」。切换即时保存，成功后开关旁给出轻提示（如「已开启 AI 能力」）。
- **核心规则**：
  1. 开关关闭时（含从未打开过的初始状态）：所有 AI 入口在所有页面不可见；前端不发出任何 AI 相关请求；后端 AI 接口对已关闭用户拒绝调用（返回 AI_DISABLED）。除 AI 区块本身外，其余页面与现状完全一致。
  2. 开关打开时：各 AI 入口出现（入口位置见各功能点）；打开动作本身不触发任何 AI 请求，也不修改任何任务数据。
  3. 开关状态是用户级配置：一个用户开关不影响其他用户。
  4. 默认值：建议默认关闭（见 A.4 第 1 条，评审拍板后回填此处）。
- **开关行为**：本功能点即开关本身。

**验收标准**

- AC 1.1 `[前端]` 设置页出现「AI 能力」区块与总开关，附关闭效果说明文案
- AC 1.2 `[系统]` 开关状态持久保存且按用户隔离；重新登录后状态保持
- AC 1.3 `[前端]` 开关关闭时，任务详情页、今日页、看板页不出现任何 AI 入口
- AC 1.4 `[系统]` 开关关闭时，调用任何 AI 接口返回 AI_DISABLED（HTTP 403），后端不调用 AI 服务
- AC 1.5 `[系统]` 开关从关闭到打开，不修改任何任务数据，不产生任何 AI 请求
- AC 1.6 `[交互]` 切换开关即时保存；保存失败时开关回弹并提示，状态与后端保持一致
- AC 1.7 `[系统]` 开关关闭时，除新增的设置区块外，其余页面渲染结果与现状一致（回归对比通过）

### US-02：AI 建议任务优先级

**用户故事**

作为登录用户，我希望 AI 根据任务内容给出 P0–P3 的优先级建议和一句理由，以便快速定级而不用逐个斟酌重要性/紧急性。

**故事详述**

- **功能描述**：在任务详情页与任务卡片上提供「AI 建议优先级」入口。点击后 AI 综合任务标题、描述、截止日、现有重要性/紧急性与耗时情况，返回一个建议优先级（P0–P3）加一句理由，展示给用户。
- **用户价值**：把「想半天怎么定级」变成「扫一眼理由、点一下采纳」，降低新建任务后的整理成本。
- **入口与交互方式**：任务详情页优先级区域旁「AI 建议」按钮；看板/今日页任务卡片上以轻量入口（图标或菜单项）提供。点击后入口显示加载状态，返回后在入口旁展示「建议 P2：理由一句话」及「采纳 / 忽略」两个动作。
- **核心规则**：
  1. 建议不直接写入：点「采纳」才把建议值写入任务的优先级字段（走现有优先级修改通道），写入后变更历史照常留痕；点「忽略」或关闭展示区，任务数据不变。
  2. 建议展示不遮挡现有信息；已有手工优先级的任务同样可以请求建议，是否采纳由用户决定。
  3. 重新点击「AI 建议」可重新生成，新建议覆盖旧建议的展示，不影响任务数据。
  4. AI 不可用或超时的行为见第五章。
- **开关行为**：总开关关闭时，本入口不出现，接口返回 AI_DISABLED，系统行为与现状完全一致。

**验收标准**

- AC 2.1 `[前端]` 开关打开时，任务详情页出现「AI 建议优先级」入口；看板/今日页任务卡片上有对应轻量入口
- AC 2.2 `[系统]` 请求后返回建议优先级（P0–P3 之一）与一句理由；理由为空视为失败（见异常表）
- AC 2.3 `[交互]` 建议展示「采纳 / 忽略」；采纳后任务优先级更新为建议值，变更历史新增一条优先级变更记录；忽略后任务数据不变
- AC 2.4 `[前端]` 加载中有明确的等待状态；加载未完成时不可重复点击
- AC 2.5 `[性能]` 建议接口响应 P95 ≤ 10s；期间页面其他操作（改状态、计时等）不被阻塞
- AC 2.6 `[前端]` 开关关闭时入口不出现，前端不发出该请求
- AC 2.7 `[审计]` 采纳产生的优先级修改在变更历史中可追溯到字段、旧值、新值与时间

### US-03：AI 生成解决方案建议

**用户故事**

作为登录用户，我希望 AI 为任务给出解决思路或下一步行动建议，以便面对模糊任务时能快速起步。

**故事详述**

- **功能描述**：在任务详情页提供「AI 方案建议」入口。点击后 AI 基于任务标题、描述、备注、所属项目与标签，生成一段解决思路（含建议的下一步行动），展示在详情页的建议区域。
- **用户价值**：解决「任务写出来了但不知道第一步干什么」的起步问题；建议落在既有字段里，不引入新的管理负担。
- **入口与交互方式**：任务详情页「下一步行动」字段附近放「AI 方案建议」按钮。返回内容展示在建议卡片中，附「填入下一步行动」「复制」「忽略」动作。
- **核心规则**：
  1. 「填入下一步行动」把建议中的下一步行动文本填进「下一步行动」输入框（表单草稿态），由用户再修改并手动保存；AI 不直接落库。「复制」把全文复制到剪贴板。「忽略」关闭卡片。
  2. 建议内容不自动覆盖用户已填写的「下一步行动」；填入动作只改草稿，用户不保存则原值不变。
  3. 同一任务可重复请求，新建议覆盖旧建议的展示。
  4. 生成内容长度受现有字段上限约束（下一步行动 500 字），超长时由前端截断提示。
- **开关行为**：总开关关闭时，入口不出现，接口返回 AI_DISABLED，系统行为与现状完全一致。

**验收标准**

- AC 3.1 `[前端]` 开关打开时，任务详情页出现「AI 方案建议」入口
- AC 3.2 `[系统]` 请求后返回解决思路文本与建议的下一步行动；两者皆空视为失败（见异常表）
- AC 3.3 `[交互]` 「填入下一步行动」只填充表单草稿，需用户手动保存才落库；不保存则任务原值不变
- AC 3.4 `[交互]` 提供复制与忽略动作；复制成功有提示
- AC 3.5 `[性能]` 建议接口响应 P95 ≤ 10s；期间页面其他操作不被阻塞
- AC 3.6 `[前端]` 开关关闭时入口不出现，前端不发出该请求
- AC 3.7 `[系统]` 填入并保存后，「下一步行动」字段的修改在变更历史留痕（与手工编辑一致）

### US-04：AI 评估任务可替代性

**用户故事**

作为登录用户，我希望 AI 判断任务是否适合交给 AI 解决，给出「可由 AI 解决 / 部分可 / 不可」的结论和理由，以便把适合的任务挑出去，把不适合的留给自己。

**故事详述**

- **功能描述**：在任务详情页「AI 可替代」区域提供「AI 评估」入口。点击后 AI 基于任务标题、描述、备注等返回三态结论（可由 AI 解决 / 部分可 / 不可）与一段说明，展示给用户，用户确认后写入现有的「AI 可替代」字段与说明字段。
- **用户价值**：现有三态字段要靠用户自己拍脑袋填，多数任务停留在「未评估」。AI 给出初步判断和理由后，用户从「评估」变成「核对」，字段才有机会真正用起来。
- **入口与交互方式**：任务详情页「AI 可替代」下拉旁放「AI 评估」按钮。返回后在旁边展示结论徽标（三色：可 / 部分可 / 不可）与说明文字，附「写入」「忽略」动作。
- **核心规则**：
  1. 结论与字段的映射：「可由 AI 解决」→ AI 可替代=是；「不可」→ AI 可替代=否；「部分可」→ AI 可替代=是且说明中标注「部分可」（现有字段只有是/否两态，部分可的表达方式见 A.4 第 3 条，评审拍板后回填）。
  2. 点「写入」才落库：写入「AI 可替代」与「AI 替代方案/说明」两个字段（走现有保存通道），变更历史照常留痕；点「忽略」则两个字段维持原值（包括维持「未评估」状态）。
  3. 用户已人工评估过的任务同样可以请求 AI 评估；写入会覆盖原值，覆盖前在确认区明示「将覆盖已有人工评估」。
  4. 说明文字超长（字段上限 2000 字）时截断提示。
- **开关行为**：总开关关闭时，入口不出现，接口返回 AI_DISABLED；用户仍可在详情页人工填写「AI 可替代」（与现状一致）。

**验收标准**

- AC 4.1 `[前端]` 开关打开时，任务详情页「AI 可替代」区域出现「AI 评估」入口
- AC 4.2 `[系统]` 请求后返回三态结论（可由 AI 解决 / 部分可 / 不可）之一与说明文字；结论缺失视为失败（见异常表）
- AC 4.3 `[前端]` 结论以三态徽标展示，颜色可区分（可 / 部分可 / 不可）
- AC 4.4 `[交互]` 「写入」前若任务已有人工评估值，展示覆盖提示；确认后两个字段更新，变更历史新增记录
- AC 4.5 `[交互]` 「忽略」后「AI 可替代」与说明字段维持原值，未评估状态不被改变
- AC 4.6 `[性能]` 评估接口响应 P95 ≤ 10s；期间页面其他操作不被阻塞
- AC 4.7 `[前端]` 开关关闭时入口不出现，人工填写「AI 可替代」的表单行为与现状一致
- AC 4.8 `[审计]` 写入产生的字段修改在变更历史中可追溯（字段、旧值、新值、时间）

### US-05：任务总耗时统计

**用户故事**

作为登录用户，我希望看到任务、按天、按项目维度的耗时汇总，以便回答「我总共花了多少时间、花在了哪里」，而不是只能逐个任务点开自己加。

**故事详述**

- **功能描述**：补齐耗时统计的汇总视图。以现有计时/工时能力为基础，分三块交付：
  1. **单任务累计（现状已有，口径修正）**：任务累计耗时已由系统维护（冗余累计列 + 每日按流水对账），详情页与卡片已在展示。本期的改动是把详情页「合计」的口径统一：现在页面底部合计是把最近 50 条明细求和，流水超过 50 条时会小于真实累计值；修正后详情页合计一律展示服务端维护的累计值，明细列表仍只列最近 50 条并注明「仅显示最近 50 条」。
  2. **按天汇总（新增）**：统计某个日期区间内，每天投入的分钟数（按计时流水与手工补录的开始时间归日，用户时区口径），以及当日投入最高的前几个任务。
  3. **按项目汇总（新增）**：统计某日期区间内，每个项目的累计分钟数与占比；未归属项目的任务单独归入「无项目」。
- **用户价值**：计时数据一直在攒，但攒出来的价值看不见。按天、按项目汇总让用户能做周回顾、项目复盘和工时沟通。
- **入口与交互方式**：
  - 单任务累计：任务详情页「耗时（实际 / 预计）」处，维持现有位置。
  - 按天与按项目汇总：今日页新增「耗时统计」卡片（默认显示今天，可切换最近 7 天 / 30 天），展开后可见按天柱状列表与按项目占比列表。是否需要独立统计页见 A.4 第 5 条。
- **核心规则**：
  1. 一切汇总以耗时流水表为权威数据源，与任务累计值的口径一致（流水之和）。
  2. 正在进行的计时分钟数为 0，不计入汇总；当日汇总中单列「进行中」提示，不并入合计。
  3. 按天归日使用用户时区（与今日视图同一口径）。
  4. 无流水的日期/项目在结果中为 0 或不展示，不报错。
  5. 统计为只读功能，不写入任何数据。
- **开关行为**：本功能点不依赖 AI、不调用 AI 服务，**不受 AI 总开关影响**，开关关闭时统计功能照常可用。

**验收标准**

- AC 5.1 `[前端]` 任务详情页「合计」展示服务端维护的累计耗时；流水超过 50 条时明细列表注明「仅显示最近 50 条」
- AC 5.2 `[系统]` 详情页合计值等于该任务全部流水分钟数之和（含手工补录，不含进行中段落）
- AC 5.3 `[前端]` 今日页出现「耗时统计」卡片，支持今天 / 最近 7 天 / 最近 30 天切换
- AC 5.4 `[系统]` 按天汇总按用户时区归日，返回区间内每天的分钟数与当日投入最高的任务（至少前 3）
- AC 5.5 `[系统]` 按项目汇总返回区间内各项目分钟数与占比，未归属项目的任务计入「无项目」
- AC 5.6 `[性能]` 统计接口响应 P95 ≤ 500ms（区间 ≤ 31 天）
- AC 5.7 `[系统]` 进行中的计时不计入合计，页面以「进行中」标识单独展示
- AC 5.8 `[系统]` 区间内无任何流水时，各图表展示空态文案，不报错
- AC 5.9 `[系统]` 开关关闭时统计功能照常可用，行为不变

### US-06：AI 拆解子任务（建议项，P1，待确认）

**用户故事**

作为登录用户，我希望 AI 把一个大任务拆成几个可执行的子任务，以便模糊的大事变成能直接开工的小步。

**故事详述**

- **功能描述**：在任务详情页提供「AI 拆解」入口。AI 基于任务标题与描述生成 3–5 个子任务建议（每个含标题与预估分钟数），以勾选列表展示，用户勾选后一键创建为该任务的子任务。
- **用户价值**：系统已支持两层父子任务，拆解是降低任务启动阻力的最直接手段；预估分钟数同时帮助用户补上「预计耗时」。
- **入口与交互方式**：任务详情页子任务区域「AI 拆解」按钮；返回勾选列表，底部「创建选中项」按钮。
- **核心规则**：
  1. 只能为无父任务的顶层任务发起拆解（系统父子只有两层）。
  2. 用户勾选并确认后才批量创建子任务，标题、预估分钟数可在创建前于输入框内修改；未勾选项被丢弃。
  3. 创建的子任务默认状态 TODO，父任务数据不变。
- **开关行为**：总开关关闭时，入口不出现，接口返回 AI_DISABLED，系统行为与现状完全一致。

**验收标准**

- AC 6.1 `[前端]` 开关打开时，顶层任务详情页出现「AI 拆解」入口；已有父任务的子任务不出现该入口
- AC 6.2 `[系统]` 请求后返回 3–5 条子任务建议，每条含标题与预估分钟数
- AC 6.3 `[交互]` 建议可勾选、可编辑标题与预估分钟数；确认后仅创建选中项为子任务（状态 TODO），父任务不变
- AC 6.4 `[性能]` 拆解接口响应 P95 ≤ 15s；期间页面其他操作不被阻塞
- AC 6.5 `[前端]` 开关关闭时入口不出现，前端不发出该请求

## 三、非功能性需求

### 3.1 安全性

| 需求项 | 说明 |
| --- | --- |
| 发送边界 | 发送给 AI 服务的内容仅限任务标题、描述、备注、重要性/紧急性、截止日、预计/实际耗时、标签与项目名等任务上下文；不得发送密码、令牌等认证信息 |
| 数据隔离 | 所有 AI 接口沿用现有 owner 鉴权：只能对自己名下的任务发起建议请求，他人任务返回 NOT_FOUND |
| 开关即断路 | 总开关关闭时，后端不调用 AI 服务（在入口处拒绝，返回 AI_DISABLED），不留任何隐式调用路径 |
| 输出约束 | AI 返回内容一律作为建议文本展示，前端按普通文本渲染，不执行其中任何内容 |
| 审计 | 所有经用户确认的 AI 建议写入（优先级、AI 可替代、下一步行动、子任务创建），沿用现有变更审计留痕 |

### 3.2 性能指标

| 需求项 | 指标 |
| --- | --- |
| 轻量建议类（优先级建议、备注建议） | P95 ≤ 10s / 8s，超时可重试，不阻塞页面其他操作 |
| 生成类（方案建议、评估、拆解、总结、复盘） | P95 ≤ 15s，前端展示进行中状态且可取消等待（关闭展示区） |
| 耗时统计接口 | P95 ≤ 500ms（区间 ≤ 31 天） |
| 开关关闭时 | 前端零 AI 请求；AI 相关资源零加载 |

### 3.3 数据一致性

- AI 建议本身不落任务数据，只有用户确认动作按现有保存通道写入；写入后 `actual_minutes`、`version`（乐观锁）、变更审计等现有机制照常生效。
- 耗时统计一律以耗时流水表为权威数据源，与任务累计值口径一致（流水之和）；进行中的计时段落分钟数为 0，不计入任何合计。
- 统计接口为实时计算，不引入第二份冗余存储；若后续引入缓存，缓存失效策略见 A.4 第 9 条。

### 3.4 存储架构（建议）

| 数据 | 说明 |
| --- | --- |
| AI 总开关状态 | 新增用户级偏好存储（单行配置即可，随用户隔离）；迁移走新版本迁移脚本，不由实体反推 |
| AI 建议内容 | 建议文本本身不持久化（展示即弃，用户采纳的是写入业务字段的确认结果）；是否留存建议历史见 A.4 第 4 条 |
| 耗时统计 | 不新增存储，按流水表现算 |
| 建议项相关 | US-06 拆解产物即子任务（写 tasks）；US-07/09 总结与复盘草稿不落库 |

## 四、逻辑断言矩阵

| Given | When | Then |
| --- | --- | --- |
| AI 总开关关闭 | 用户浏览任意页面 | 全部 AI 入口不可见，前端零 AI 请求，除设置页新增区块外页面与现状一致 |
| AI 总开关关闭 | 直接调用任意 AI 接口 | 返回 AI_DISABLED（HTTP 403），后端不调用 AI 服务 |
| AI 总开关打开 | 任务详情页点击「AI 建议优先级」 | 返回建议优先级与理由；采纳前任务数据不变 |
| AI 总开关打开 | 采纳优先级建议 | 任务优先级更新为建议值，变更历史新增记录 |
| AI 总开关打开 | 忽略优先级建议 | 任务优先级与一切字段不变 |
| AI 总开关打开 | 点击「AI 方案建议」并「填入下一步行动」后不保存 | 仅表单草稿被填充，任务「下一步行动」原值不变 |
| AI 总开关打开 | 点击「AI 方案建议」并保存 | 「下一步行动」更新，变更历史留痕 |
| AI 总开关打开 | 对已人工评估的任务执行 AI 评估并写入 | 覆盖前展示覆盖提示；写入后两个字段更新并留痕 |
| AI 总开关打开 | AI 评估返回「部分可」 | 按拍板结论落库（见 A.4 第 3 条），未拍板前默认「AI 可替代=是 + 说明标注部分可」 |
| AI 总开关打开 | 对他人名下任务发起任意 AI 请求 | 返回 NOT_FOUND，不泄露任务存在性 |
| AI 服务超时或不可用 | 用户点击任意 AI 入口 | 展示失败提示与「重试」；任务数据不变；不阻塞页面其他操作 |
| AI 总开关关闭 | 用户使用耗时统计 | 统计功能照常可用，结果口径不变 |
| 任意开关状态 | 查看任务详情合计 | 合计等于该任务全部流水之和；流水超 50 条时明细列表注明只显示最近 50 条 |
| 任意开关状态 | 查看按天/按项目统计，区间内无流水 | 展示空态文案，不报错 |
| 计时进行中 | 查看按天汇总 | 进行中段落不计入合计，单独展示「进行中」标识 |
| 未登录 | 调用任意 AI 或统计接口 | 返回 UNAUTHORIZED（HTTP 401） |
| AI 总开关打开 | 每日总结/周复盘请求当期无数据 | 返回空态文案，不调用 AI 服务 |
| AI 总开关打开 | 对有父任务的子任务发起 AI 拆解 | 入口不出现；直接调用返回错误提示（子任务不可再拆） |

## 五、异常处理规范

### 5.1 AI 能力异常

| 场景 | 用户提示 | 系统行为 |
| --- | --- | --- |
| 总开关已关闭 | 不展示入口；直接调用时提示「AI 能力未开启」 | 返回 AI_DISABLED（HTTP 403），后端不调用 AI 服务 |
| AI 服务超时 | 「AI 没有及时返回，稍后再试」 | 返回 AI_TIMEOUT；任务数据不变；提供重试入口 |
| AI 服务不可用 / 调用失败 | 「AI 服务暂时不可用，稍后再试」 | 返回 AI_UNAVAILABLE；任务数据不变；提供重试入口 |
| 调用频率超限 | 「请求太频繁，请稍后再试」 | 返回 AI_RATE_LIMITED；建议类接口按用户限流（阈值见 A.4 第 6 条） |
| 返回内容为空或不含必要字段 | 「AI 没有给出有效建议，请重试」 | 按失败处理（AI_EMPTY_RESULT），不展示空卡片 |
| 任务不存在或属于他人 | 与现有任务接口一致：「任务不存在」 | 返回 NOT_FOUND（HTTP 404） |
| 采纳时任务已被修改（乐观锁冲突） | 与现有编辑接口一致：「任务已被他人修改，请刷新后重试」 | 返回 VERSION_CONFLICT（HTTP 409），建议内容保留可重新采纳 |

### 5.2 耗时统计异常

| 场景 | 用户提示 | 系统行为 |
| --- | --- | --- |
| 日期区间非法（起 > 止 / 超 31 天） | 「时间范围不正确，最长支持 31 天」 | 返回 VALIDATION_FAILED（HTTP 400），不执行统计 |
| 区间内无流水 | 空态文案「这段时间还没有计时记录」 | 返回空集，HTTP 200 |
| 未登录 | 跳转登录页 | 返回 UNAUTHORIZED（HTTP 401） |

### 5.3 异常返回示例

```json
{
  "status": 504,
  "code": "AI_TIMEOUT",
  "error": "Gateway Timeout",
  "message": "AI 没有及时返回，稍后再试",
  "timestamp": "2026-10-24T09:30:00Z"
}
```

错误体沿用系统统一格式（status / code / error / message / timestamp），新增 AI 相关错误码：AI_DISABLED、AI_TIMEOUT、AI_UNAVAILABLE、AI_RATE_LIMITED、AI_EMPTY_RESULT；错误码只增不改，前端按 code 判分支。

```

        │

   ▼          ▼

   ▼          ▼

 通道写入，   完全不变
 变更留痕
```

### A.2 角色与权限矩阵

系统无角色体系（用户表无角色列），数据按用户隔离，本人只能操作本人数据：

| 功能 | 登录用户（本人） | 其他用户 |
| --- | --- | --- |
| AI 总开关读写 | ✅（仅本人设置） | — |
| 优先级建议 / 方案建议 / AI 评估 | ✅（仅本人任务） | ❌（表现为任务不存在） |
| 采纳建议写入任务字段 | ✅（仅本人任务） | ❌ |
| 耗时统计（单任务/按天/按项目） | ✅（仅本人数据） | ❌ |
| 拆解子任务 / 总结 / 复盘草稿 | ✅（仅本人数据） | ❌ |

### A.3 与其他模块关系

| 模块 | 关系 |
| --- | --- |
| task | AI 建议的读取与写入对象；优先级、AI 可替代、下一步行动、子任务均落在任务现有字段与通道上 |
| timelog | 耗时统计的唯一权威数据源；US-08 的建议触发点在结束计时流程；AI 建议不直接修改耗时流水 |
| 设置页 | AI 总开关的宿主区块；统计入口的候选位置之一 |
| 今日页 / 看板 | 优先级建议的轻量入口位置；统计卡片的宿主页面；今日页同时是每日总结入口 |
| 调度（scheduler） | 现有每日对账保证累计值与流水一致，统计口径依赖该机制，不需要新任务 |
| 审计（audit） | 所有采纳写入沿用现有变更历史；AI 来源本身暂不单独立项标注（见 A.4 第 4 条） |
| 认证（auth） | 复用现有登录与 owner 鉴权；AI 服务密钥等配置走服务端环境变量，不下发前端 |
| 数据库已建未用表 | ai_opportunities / skills / weekly_reviews 已建表但无业务模块，本期不启用，不在其上叠加功能 |

### A.4 待确认项（评审拍板）

1. **AI 总开关默认值**：建议默认关闭（首访用户看不到任何 AI 入口，主动开启才生效）；若产品倾向让用户先体验，可选默认开启。拍板后回填 US-01。
2. **AI 服务与模型选型、密钥配置方式**：外部大模型 API 还是自托管服务；密钥走环境变量（与现有 APP_AUTH_JWT_SECRET 同模式）。影响 3.2 的时延指标与第五章限流策略。
3. **「部分可」的落库表达**：现有 `ai_replaceable` 是布尔字段。方案 a：部分可 → 是 + 说明标注部分可（成本最低，推荐）；方案 b：扩展字段或迁移到已建的 `ai_opportunities.ai_can_replace`（YES/PARTIAL/NO/UNKNOWN，需新增模块）。拍板后回填 US-04。
4. **AI 建议是否留存历史**：方案 a：不留存，展示即弃（推荐，零存储成本）；方案 b：留存建议原文并标注 AI 来源。影响审计字段设计。
5. **统计与复盘入口形态**：今日页卡片（推荐，少一页导航）还是独立统计页；周复盘草稿入口放今日页还是设置页。
6. **AI 调用限流阈值**：每用户每分钟/每天的调用次数上限，防止误点连击与成本失控。
7. **按天汇总的时区口径**：建议沿用今日视图的用户时区口径（推荐）；若需与其他系统对账，确认目标系统的时区约定。
8. **P1 建议项（US-06 ～ US-09）取舍**：哪些纳入本期、哪些延后，按开发资源拍板；未纳入的保留在本文档作为后续规划。
9. **统计缓存策略（如引入）**：默认不缓存、每次现算；若性能不达标再引入缓存并定义失效时机（计时开始/结束/补录/对账后）。
